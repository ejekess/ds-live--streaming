# 接到真实抖音直播间

默认的 `mock` 源是剧本，用来开发和演示。真的上播要换成下面三种之一。

先说清楚一件事：**抖音没有开放「读别人直播间弹幕」的公开接口**。下面所有方式都建立在
「用你自己的浏览器打开你自己的直播间」这个前提上，属于非官方能力，随时可能被平台改掉。
详见文末的合规提醒。

---

## 方式一：`cdp`（推荐，无需逆向签名）

原理：用本机浏览器打开直播间页面，让**页面自己**完成握手、鉴权和心跳，
我们只在旁边监听它收到的 WebSocket 帧，把 protobuf 解出来。

好处是绕开了 `a_bogus` / `X-Bogus` 这类签名算法——那玩意儿官方一改就全废，
而且拿到浏览器外重放很容易被判定异常。

### 1. 安装依赖

```powershell
npm install --ignore-scripts
```

`playwright-core` 在 `optionalDependencies` 里。它**不下载 Chromium**，
直接用你系统里已有的 Edge/Chrome（Windows 11 自带 Edge）。

### 2. 配置

编辑 `config/config.json`：

```json
{
  "source": {
    "kind": "cdp",
    "cdp": {
      "roomUrl": "https://live.douyin.com/123456789",
      "browserChannel": "msedge",
      "headless": false,
      "userDataDir": "data/browser-profile",
      "warmupMs": 6000
    }
  }
}
```

- `roomUrl`：你的直播间地址。开播后在「直播伴侣」或网页端复制，
  形如 `https://live.douyin.com/数字`。
- `headless`：**建议 false**。抖音对无头环境有风控，真窗口更稳；
  反正你本来就在直播，多开一个窗口不碍事。
- `userDataDir`：浏览器配置目录。第一次会弹登录页，扫码登录一次之后
  这个目录里就留着 cookie，下次不用再扫。**这个目录等同于你的账号，别传给任何人。**

### 3. 启动

```powershell
node src/index.mjs
```

浏览器会自动打开直播间。等日志里出现：

```
[cdp] 已挂上推送信道：wss://webcast....
```

就说明接上了。此时管控台的「现场」标签页会开始滚动真实弹幕。

### 4. 如果一直没反应

按顺序排查：

1. **日志里有没有 `已挂上推送信道`** —— 没有就是没找到 WebSocket。
   新版页面可能换了路径，改 `src/sources/cdp.mjs` 顶部的 `PUSH_URL` 正则。
2. **有信道但没有事件** —— 打开浏览器控制台看 `window.__DSH_PET_ERROR__`；
   或者在 `src/douyin/decode.mjs` 里临时 `console.log(meta)`，
   看 `unknown` 里有没有新方法名（抖音偶尔会加 `WebcastXxxMessage`）。
3. **页面弹了验证码** —— 手动过一次即可，`userDataDir` 会记住。
4. **90 秒没有任何帧** —— 看门狗会自动重载页面；连续重载说明被风控了，
   换个网络或稍后再试。

## 方式二：`exec`（接你自己的采集器）

如果你已经有成熟的抓取器（Python 的 DouyinLiveWebFetcher、Go 的 douyinLive 等），
不用改它，让它往 stdout 一行输出一条 JSON 就行：

```json
{"type":"comment","user":{"name":"海观","id":"u1"},"text":"主播好可爱"}
{"type":"gift","user":{"name":"海观"},"gift":{"id":"玫瑰","name":"玫瑰","diamonds":1,"count":3}}
{"type":"like","user":{"name":"海观"},"count":12,"total":480}
{"type":"enter","user":{"name":"海观"}}
{"type":"follow","user":{"name":"海观"}}
{"type":"stats","viewers":86,"likes":480}
```

配置：

```json
{
  "source": {
    "kind": "exec",
    "exec": {
      "command": "python",
      "args": ["your_fetcher.py", "123456789"],
      "cwd": ""
    }
  }
}
```

进程退出会自动重启（间隔 3 秒）。要把上游的日志和 JSON 分开：
**只有 stdout 会被解析**，日志请走 stderr。

> 用这种方式接 AGPL 的抓取器是安全的：它是独立进程，不通过 import 传染许可。
> 直接 `import` 进来则会。

## 方式三：`replay`（回放）

把一场真实直播录成 JSONL，之后反复调参、复现 bug：

```json
{"source": {"kind": "replay", "replay": {"file": "data/sample-live.jsonl", "speed": 1, "loop": true}}}
```

仓库里带了一份 `data/sample-live.jsonl`（20 条，含弹幕/问句/广告/五档打赏/关注）。
`speed` 是倍速，`loop` 决定放完是否重播。

## 合规提醒（请真的读一下）

1. **这是非官方接口。** 抖音的用户协议通常禁止「未经授权抓取/自动化操作」。
   用自己账号、自己直播间、量级不大的场景，实践中风险较低，但**风险不由我承担**。
2. **别做灰产。** 刷人气、机器人刷礼物、虚假互动、批量小号——这类行为平台打击得很重，
   而且一旦被判定，损失的是你的账号。
3. **虚拟形象直播需要报备。** 抖音对「虚拟主播 / 数字人直播」有专门规则，
   部分场景需要在开播时选择对应类型并遵守标识要求。上播前请先读平台的《直播行为规范》。
4. **打赏是真实收入。** 礼物折现涉及平台分成与个人所得税，别当成游戏币。
5. **观众的话不要全信。** 这个项目已经把所有观众输入当「数据」而不是「指令」处理
   （见 `src/brain/guard.mjs`），但如果你自己接了别的大模型服务，务必保留这层过滤。

## 附：真机实测记录（2026-10-30）

第一次拿真实直播间跑通，记下几件只有真跑才会发现的事。

### ① `payloadEncoding` 不可信，要按魔数判断

抖音现在把帧的 `payloadEncoding` 标成 **`"pb"`**，但 payload **仍然是 gzip**。
如果照着字段走（`if (enc === 'gzip') gunzip`），就会把压缩块当 protobuf 解，
报 `invalid wire type 7 at offset 12`——一个看起来像 proto 版本对不上、实际是没解压的错。

正确做法是看前两个字节：

```js
if (body[0] === 0x1f && body[1] === 0x8b) body = gunzipSync(body);
```

| 项目 | 值 |
| --- | --- |
| 房间 | `live.douyin.com/633710243936`（公开直播） |
