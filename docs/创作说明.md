# 创作说明

## 为什么选这个题

我看了一圈虚拟主播：形象一个比一个精致，但"反应"是死的——弹幕照念，礼物只会说谢谢，送一块和送一万没区别。

真正让人愿意留下来刷礼物的，是**"她知道你花了多少钱"**。所以我把核心放在打赏分级演出上：金额换动作、换表情、换特效，五档递进。猜词游戏则是给不花钱的观众一个开口的理由。

## 需求分析（占时间最多）

动手前我列了四条硬约束，后面每个设计决定都从这来的：

1. **直播间不能卡**——演出、语音、游戏三套时序会打架，所以拆成纯状态机 + 定时器驱动，逻辑能单测。
2. **不能烧 token**——输入限长、输出限长、每分钟/每天双上限、6 秒超时；更关键的是给游戏预留额度，否则闲聊会把猜词的调用吃光。
3. **不能碰版权**——点歌功能做完直接停用，代码留着但不启用。
4. **不能被弹幕注入**——模型只拿纯文本、没有任何工具权限，答案和流程控制都在宿主代码里。

## 用了哪些 AI 工具

全程用 DeepSeek Harness 做结对开发：我出需求、定架构、做取舍，它写实现和自检。关键判断（比如"答案不能进 prompt""模型不能有结束权"）是我定的，它负责落地和找出我没想到的边界。

## 踩的坑

都是"不报错但静默失效"：抖音把 gzip 报文标成 `pb`，我信了字段名，解出 0 条；分发钩子漏转发一个，开场动画从来没显示过；父进程退出后日志管道写满，整个服务卡死。共同点是——**只有真跑一遍才会暴露**。
